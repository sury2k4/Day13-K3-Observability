Root cause:
`app/mock_rag.py:retrieve()` sleeps 2.5 seconds whenever STATE["rag_slow"] is enabled.
The traces show the same roughly 2.65–2.99 second generation latency, while error_breakdown is empty;
the matching logs prove the affected refund requests experienced the delay.

Mitigation and verification:
The official incident was disabled. Follow-up challenge requests had latency 150–155 ms
(for example correlation_id=req-76f9efad), confirming recovery.

Fix action:
Disable the incident flag immediately; in production, remove the injected delay and add a bounded
retrieval timeout with a fast fallback response.

Preventive measure:
Alert on latency_p95_ms > 3000 for 10m, add retrieval-span latency metrics, and test timeout/fallback
behavior in load tests before release.
